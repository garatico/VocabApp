# VocabApp

A vocabulary learning app for Spanish, French, Italian, Portuguese, German and
Dutch: picture quizzes, recall practice, conjugation drills, and word tables,
backed by a curated word database with frequency rankings.

## Stack

TypeScript end to end — Express API + SQLite (better-sqlite3) on the server and a Vite-bundled
vanilla-TS SPA on the client. The vocabulary database is built by a separate Python pipeline
(see below). The same client ships four ways: a static website, a Windows desktop app (Tauri), an
Android app (Capacitor) and, for development, behind the Express server.

## Quick start

```bash
npm install
npm run dev        # API on :3000, Vite dev server on :5173
```

Open http://localhost:5173 (app) or http://localhost:5173/admin (admin panel,
development only).

## Common commands

```bash
npm test               # vitest (sql.js in-memory shim — never touches the real DB)
npm run lint           # eslint over src/, tests/, scripts/
npm run typecheck      # tsc for client + server
npm run validate       # truncation / null-byte pre-flight check
npm run build          # production bundle → dist/ (served by the Express server)
npm run build:static   # the website: plain files in dist/, no server (see Deploying)
```

## Deploying

The hosted site is a **static site** (`render.yaml`, `runtime: static`): `npm run build:static` writes the
app, one JSONL file per language, and the photos/emoji into `dist/`, and a CDN serves them. There is no
Node process in production — the old Node web service held every language in memory and kept running out
of it on a small instance. The admin panel and `/api` are not part of that deploy.

The desktop and Android apps bundle their data instead of fetching it:

```bash
npm run build:windows   # Tauri installer (needs Rust)
npm run build:android   # debug APK (needs JDK 21–24 and the Android SDK; see CLAUDE.md)
npm run native:check    # report which of the above tooling is missing
```

## Where the data comes from

This app does not build its own vocabulary. It is handed `data/vocabulary.db`
by **VocabApp-Data**, a separate project that runs the corpus pipeline. It lives in its own repository
folder, next to this one (`../VocabApp-Data`), with its own README, tests and CI.

```bash
cd ../VocabApp-Data && python pipeline/pipeline.py everything --write
```

The interface is the file. `DATA_DIR` points both projects at the same
directory, so the database can live anywhere:

```bash
DATA_DIR=/srv/vocab-data npm start
```

The app checks the database it is given at startup, against what it says it
needs in `src/server/lib/data-requirements.ts`. A missing column it reads is
fatal and names the fix — it would throw on the first request anyway, and
failing at boot beats failing under a user. Data that is merely older than
expected warns and carries on.

## Layout

```
src/server/    Express app, routes, middleware, SQLite loader, conjugation engine
src/client/    SPA + admin panel (Vite multi-page: index.html, admin.html)
tests/         vitest suites (server API + client utils)
data/          vocabulary.db, images, emoji, svgs, audio — what the app is given
docs/          architecture notes, schema docs, guides
scripts/       build scripts (static web, native), exporters, validators
src-tauri/     Windows desktop shell (Tauri)
mobile/        parked React Native experiment — not in development
```

`android/` is generated by Capacitor and gitignored; `npx cap add android` recreates it.

Configuration lives in `.env` (see `.env.example`). The data directory can be
relocated with `DATA_DIR`, and server log verbosity with `LOG_LEVEL`
(`debug` | `info` | `warn` | `error` | `silent`). Admin routes are
development-only, localhost-only, and optionally protected with `ADMIN_SECRET`.

`DATA_DIR` is deliberately the same variable name VocabApp-Data reads, so one
setting points producer and consumer at the same directory.

CI (GitHub Actions, `ci.yml`) runs on every push and PR: validate, lint, typecheck, unit tests and build,
plus the Playwright end-to-end suite (including the axe accessibility audit). The data pipeline has its
own CI in VocabApp-Data. A husky pre-commit hook runs the validate check plus eslint on staged files.

See `CLAUDE.md` for contributor/agent notes and `docs/` for deeper
documentation.
